# Has this been shown before? Prior-work check, 2026-10-11

Two search rounds by Claude agents: nine angles, about 350 web searches. Round 1 checked 36 close matches against the papers themselves, and round 2 re-checked the seven papers the verdicts lean on most. "Not found" means these searches didn't find it, not that it doesn't exist. Raw outputs are in the session logs; this file keeps only papers whose pages were fetched.

## Short answer

The broad problems are known. Earlier studies have shown three things. Citations don't always reflect what an answer rests on. Models answer from memory even when told to use only the document. And older Claude models resisted wrong documents more than GPT models did. What wasn't found is this experiment's specific measurement. That measurement has four parts. The documents are built so they can't contain the answer. The citations attached to remembered answers are real verbatim quotes. The labels the model itself gives (document, memory or inference) are scored against that known source. And all of it runs on current Claude and GPT API models.

## Gaps in the search

- PFaithBench ([2610.07894](https://arxiv.org/abs/2610.07894)) may be the closest work for F5 and F9. It measures answers leaked under insufficient context across 39 models. Its page was rate-limited, so it was read only through a summary, and its model list and per-model numbers are unchecked.
- Papers citing Wallat et al. and van Dort & Heuss couldn't be listed, so later work measuring this exact failure could be missed.
- The Claude Opus 5.5 system card and the FACTS Grounding v2 text weren't read in full.
